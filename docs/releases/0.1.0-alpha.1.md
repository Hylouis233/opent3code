# OpenT3Code 0.1.0-alpha.1

**Source-only developer preview. Not a signed desktop release or production certification.**

## Added

MiniMax Code and DeepSeek Harness now have independent ACP provider drivers and settings entries. The integration handles text prompts, assistant/reasoning/tool updates, one-shot permission requests, cancellation, scoped process cleanup and native session resume. Resume cursors are bound to the same driver, instance, workspace and CLI home.

The installable `@opent3code/dsh-plugin` bundle creates the dedicated DSH `opent3code` ACP profile. It uses workspace-write policy, asks for approvals and disables session telemetry. Its setup helper only initializes a new profile and supplies explicit native dependency build approvals; it does not overwrite an existing profile.

A source-preview launcher creates separate OpenT3Code state and initializes Supervised permissions without changing existing T3, DSH or MiniMax account data. See [the preview guide](https://github.com/Hylouis233/opent3code/blob/main/docs/user/opent3code-preview.md) and the DSH companion README in the source package.

## Install

Use Node.js 24.13.1 or newer 24.x, Vite+, and your own authenticated native CLI. Unpack the source ZIP, run `vp i`, then `node scripts/opent3code-preview.mjs`. Open the full pairing URL printed by the development runner; never share its credential in a group or screenshot. Start with a disposable workspace.

MiniMax Code targets `@minimax-ai/code@0.4.7` and launches `mcode acp`. DSH targets CLI `@deepseek-ai/dsh@0.1.5-rc.1` with the companion's ACP/base/application dependencies at `0.1.5-rc.2`. Install the DSH profile following its README before enabling the provider. Retain its dependency lockfile. Native CLI authentication, account entitlements and model selection remain the user's responsibility.

## Limits and verification scope

Only Supervised text sessions are supported by the new adapters. Attachments, plan-mode switching, mid-turn steering, rollback, native history import and background title/commit generation are not advertised. DSH resume does not replay historical messages and its updates can be committed semantic messages rather than individual tokens.

The release requires successful CI on its exact main commit. Regression tests use controlled ACP subprocess fixtures. Official CLI protocol probes do not certify live paid-account generation. No authenticated end-to-end model task, all-platform GUI certification, independent security audit or signed binary upgrade is claimed.

Internal T3 package names, desktop identities and distribution scripts remain inherited. This release supplies source and a DSH profile bundle, not a branded `.app`, DMG, EXE, AppImage, npm server publication or a multi-user hosting service. Do not repackage the inherited installer as an isolated OpenT3Code install.

## Artifacts and rollback

`opent3code-source-0.1.0-alpha.1.zip` contains the exact tagged source; `opent3code-dsh-plugin-0.1.0-alpha.1.tgz` contains the companion bundle. `SHA256SUMS` covers both archives and `RELEASE.json`, which records the commit and CI run. Verify checksums before use.

Stop the preview before switching versions. Keep a backup of its separate data directory; there is no downgrade migration guarantee. Removing the provider or companion bundle does not delete native sessions. Report the version, platform, CLI version and a redacted minimal reproduction to the maintainer, not upstream T3 support.
